# نبض على Cloudflare — الخطة المجانية

هذه نسخة مستقلة من لوحة الحملات تستضيف الواجهة وAPI على Worker واحد اسمه `testcodex`، وتحفظ البيانات في D1 باسم `nabdh-cms`. لا تحتاج VPS أو دومين؛ يستخدم النشر عنوانًا من نوع `https://testcodex.YOUR-SUBDOMAIN.workers.dev`. Firebase FCM هو مزوّد الإشعارات. GitHub Pages يبقى لمعاينة تطبيق Android فقط.

## حالة العمل

اسم القاعدة `nabdh-cms` ومعرّفها `da3f2841-b8a5-4d5e-b662-01487cdbd1a7` محفوظان في `wrangler.jsonc` بناءً على معلومات المستخدم. هذا معرّف عام، وليس مفتاح وصول. لم تُنشر هذه النسخة على حساب Cloudflare بعد.

نجحت اختبارات محلية على runtime الخاص بـWorkers وقاعدة D1 محلية، مع محاكاة اتصالات OAuth وFCM: حماية المدير الأول، cookies وCSRF، الربط لمرة واحدة تحت طلبات متزامنة، تدوير رمز الجهاز وإلغاء الربط، منع إرسال الحملة مرتين، تسجيل قبول FCM والحالات المجهولة، وجدولة دفعات صغيرة. اختبار المتصفح يغطي تسجيل الدخول، إنشاء الحملة، المعاينة، رمز الربط، وفحص Firebase، وعرض الهاتف. الاتصالات المحاكاة لا تثبت استقبال إشعار على هاتف أو الالتزام بميزانية CPU في البيئة الحقيقية.

## النشر من GitHub دون مفاتيح وصول في المحادثة

1. ضع Database ID الحقيقي في `cloudflare/wrangler.jsonc` بدل UUID المكوّن من أصفار، واترك binding اسمه `DB` وdatabase_name اسمه `nabdh-cms`.
2. من **Workers & Pages** أنشئ **Worker** واختر ربط/استيراد مستودع GitHub `CashAppSy/TestCodex`، وليس نشر Pages الذي بدأت بإعداده سابقًا.
3. اختر فرع `main`، واضبط **Root directory** إلى `cloudflare`، وNode.js إلى `24` إذا أتاح إعداد البناء ذلك.
4. استخدم **Build command**: `npm run build`.
5. استخدم **Deploy command**: `npm run db:remote && npm run deploy`. إذا كانت الواجهة تطلب أمر تثبيت، استخدم `npm ci`. خطوة البناء لا تحتاج أسرار Firebase.
6. ابدأ النشر، ثم تأكد في **Bindings** من وجود D1 binding باسم `DB` للقاعدة `nabdh-cms`. إذا رُفضت خطوة migrations بسبب صلاحيات تكامل البناء، استخدم مسار Wrangler المحلي أدناه أو نفّذ ملف SQL الأول من وحدة D1 قبل إعادة نشر Worker؛ لا ترقِّ الخطة المدفوعة لمعالجة خطأ صلاحيات.
7. من إعدادات Worker، قسم **Variables and Secrets**، أضف كـ**Secret**:
   - `BOOTSTRAP_TOKEN`: قيمة عشوائية خاصة بطول 32 حرفًا على الأقل؛ تحتاجها لإنشاء المدير الأول فقط. لا ترسل قيمتها في المحادثة.
   - `FCM_SERVICE_ACCOUNT_JSON`: محتوى ملف حساب خدمة Firebase كاملًا كسرّ، وليس متغيرًا عامًا. يجب أن تخص البيانات مشروع `nabed-549b0`. استخدم مفتاحًا بديلًا للمفتاح الذي رُفع سابقًا في المحادثة قبل النشر الحقيقي.
8. احفظ تغييرات الأسرار وانشرها إن طلبت الواجهة ذلك، ثم افتح عنوان Worker. أنشئ المدير ببريد وكلمة مرور من 12 حرفًا على الأقل ورمز التهيئة. لا يُسمح بإنشاء مدير ثانٍ. يمكن إزالة BOOTSTRAP_TOKEN بعد اكتمال الإعداد.
9. في **Triggers / Cron Triggers** تحقق من الجدول `* * * * *`؛ يتم توفيره من wrangler config. لا تضف عدة triggers مكررة.
10. من اللوحة، افتح **الإعدادات** واضغط **فحص إعداد Firebase دون إرسال**. بعد نجاحه، اربط هاتف Android بالعنوان ورمز من **الأجهزة والربط**، ثم اختبر حملة تستهدف `android` وشريحة `test`.

لا تطلب Workers Paid أو قاعدة مدفوعة. هذه النسخة تستخدم ميزات متاحة في الخطة المجانية، لكن لها حدود طلبات وCPU وقراءات/كتابات ومساحة. راقب الاستهلاك والأخطاء في الحساب؛ تجاوز حدود الخطة المجانية قد يوقف الطلبات ولا يعني أن عليك قبول ترقية. نجاح الاختبارات المحلية لا يثبت أن أداء الحساب الفعلي مناسب لكل حجم حملة. الواجهة تعرض آخر 100 حملة/جهاز/نتيجة فقط.

## النشر باستخدام Wrangler على حاسوبك

إذا لم ترغب في تكامل GitHub الخاص بـCloudflare، بعد وضع Database ID:

```sh
cd cloudflare
npm ci
npx wrangler login
npm run db:remote
npm run build
npm run deploy
npx wrangler secret put BOOTSTRAP_TOKEN
npx wrangler secret put FCM_SERVICE_ACCOUNT_JSON
```

تتم المصادقة في المتصفح. أدخل القيم في المطالبات الآمنة على حاسوبك أو من واجهة إعدادات Worker، ولا تضمّنها في أوامر Git أو ملفات عامة. هذه الأوامر تنشر على حسابك وتطبق جداول D1؛ لم تُنفذ على حساب المستخدم من بيئة Codex الحالية.

## التطوير المحلي

```sh
cd cloudflare
npm ci
npm run db:local
npm run build
npm test
npm run dev
```

ضع رمز تهيئة محليًا في الملف Git-ignored `.dev.vars` بصيغة `BOOTSTRAP_TOKEN=...`. ليس مطلوبًا لإجراء اختبارات API لأن الاختبارات تستخدم قاعدة وحسابًا معزولين وبيانات مصطنعة. لتشغيل اختبار المتصفح أيضًا، ثبّت Chromium الخاص بـPlaywright أو استخدم Chromium النظام:

```sh
RUN_BROWSER_TEST=1 PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm test
```

في بيئة Codex، اجعل cache/log/config في مسارات قابلة للكتابة: `npm --cache /tmp/testcodex-npm-cache ci`، و`XDG_CONFIG_HOME=/workspace/.nabdh-cloudflare-config WRANGLER_LOG_PATH=/tmp/nabdh-wrangler.log WRANGLER_SEND_METRICS=false` لأوامر Wrangler. لا تفترض أن بيانات SQLite السابقة نُقلت؛ هذه قاعدة جديدة، ولا توجد migration تلقائية من نسخة VPS.

## سلوك الإرسال

تستخدم إشعارات Android صورة اللوغو الأصلي الشفاف عبر `android.notification.image`. رابط الصورة العام مضبوط في `NOTIFICATION_LOGO_URL` داخل `wrangler.jsonc`؛ عند تغيير عنوان Worker حدّث الرابط أيضًا. لا يتطلب هذا الرابط سرًّا. الملف الأصلي أقل من حد FCM للصورة (1 ميغابايت). تطبيق Android 0.1.4 يضم نسخة اللوغو نفسها لإشعارات المقدمة؛ ظهور الصورة في الخلفية يعتمد على نجاح تحميلها على الهاتف. يبقى رمز شريط الحالة أحادي اللون كما يتطلب Android.

لإعادة إرسال حملة مكتملة، اضغط **إعادة إرسال** بجانبها وأكد الجمهور في نافذة التأكيد. تُنشأ نسخة بنفس الرسالة والمنصة والشريحة والمشتركين المحددين والرابط ثم يبدأ إرسالها مباشرة، دون نقل الموعد القديم أو نتائج الإرسال. الإلغاء لا ينشئ نسخة ولا يرسل. لتعديل المحتوى أو حفظ موعد جديد، استخدم **نسخ للتعديل**؛ هذا الخيار ينشئ مسودة فقط. إذا تعذر بدء الإرسال، تبقى النسخة في قائمة الحملات ويمكن مراجعة حالتها ومعالجة السبب. تتحدث النتائج تلقائيًا كل خمس ثوانٍ أثناء الإرسال عندما تكون الصفحة ظاهرة، ويظهر زر إعادة الإرسال عند اكتمال الطلب. يستهدف الإرسال الجديد الجمهور النشط وقت تأكيده، بما فيه الأجهزة التي استقبلت الطلب السابق؛ يبقى سجل الحملة الأصلية ونتائجها محفوظًا. لا تحتاج هذه الميزة ترحيلًا جديدًا لقاعدة البيانات أو تحديث تطبيق Android.

عند تأكيد إرسال حملة، يُحجز جمهورها في معاملة D1 ذرية لمنع إرسال مكرر. تُرسل خمسة طلبات بحد أقصى في الدفعة، ويتابع العامل دفعات الحملات المفتوحة كل دقيقة. الطلبات تُسجّل كـ`accepted` عند قبول FCM؛ الوصول والفتح لا يُقاسان بهذه الحالة. عند انقطاع اتصال غير معلوم النتيجة، تسجل `unknown` ولا تُعاد تلقائيًا. الحجز الذي انقطع أثناء التنفيذ يعامل كمجهول بعد خمس دقائق. حملات بلا أجهزة نشطة تبقى مجدولة حتى يصبح جمهورها متاحًا. عند خروج العامل قبل الاستكمال، يستأنف الطلبات التي لا تزال `pending` فقط.

الرمز صالح عشر دقائق ولمرة واحدة، ويربط جهاز Android بشريحة `test`. الهاتف يحتفظ باعتماد خاص بالجهاز في SecureStore؛ لا يستخدم مفتاح حساب الخدمة. مسارات `/api/mobile/pair` و`/api/mobile/device` متوافقة مع تطبيق Android الموجود في `mobile/`.


## إشعارات عمليات تجريبية

النسخة 0.1.7 تضيف `0002_payment_demo.sql` وجدول عمليات اختبار مستقل. يجب تطبيق الترحيل قبل نشر العامل: أبقِ أمر النشر في Cloudflare **`npm run db:remote && npm run deploy`** مع Root directory **`cloudflare`** وفرع **`main`**. هذا لا يعدّل سجلات الحملات القديمة. الترحيل يتكفل به الأمر الأول عند النشر. إن كنت تنشر يدويًا دون أمر الترحيل، طبّق الملف في D1 قبل نشر العامل.

`ENABLE_PAYMENT_DEMO` مضبوط إلى `true` لاختبار الأجهزة النشطة في شريحة `test` فقط. لتعطيل إنشاء/قراءة العمليات والإرسال المؤجل التجريبي اجعله `false` وأعد النشر. لا تستخدم المسار التجريبي لتأكيد دفع حقيقي؛ التكامل الإنتاجي يحتاج هوية المشترك والتحقق من الدفع على الخادم.

`POST /api/mobile/payments` يحتاج جلسة الجهاز ويقبل `requestId` (12–80 حرفًا من الحروف والأرقام و `_` و `-`)، مبلغًا صحيحًا 1–10,000,000 ل.س، وخيار `delayed` للتجربة في الخلفية. يسجّل تسديدًا تجريبيًا ويرسل إشعارًا إلى جهاز صاحب الجلسة فقط. مفتاح منع التكرار فريد لكل جهاز وطلب، وبدء الإشعار محمي بتحديث شرطي ذري. إعادة الطلب بالمعرّف والمبلغ نفسيهما تعيد السجل الموجود؛ تغيير المبلغ يرجع 409. لا يوجد إرسال تلقائي آخر بعد نتيجة غير معروفة.

`GET /api/mobile/payments` يعيد آخر 20 عملية للجهاز؛ `?id=...` يجلب عملية بعينها للجهاز نفسه حتى إن كانت أقدم. اللوحة تعرض آخر 100 عملية تجريبية وحالة الإشعار. لا تُرسل أسرار Firebase إلى التطبيق، ولا يُستهدف جمهور الحملات من هذا المسار.


## إعداد Firebase مفقود بعد النشر

رسالة «أضف سر Firebase قبل الإرسال» أو «أضف إعداد Firebase أولًا» تعني أن `FCM_SERVICE_ACCOUNT_JSON` غير موجود في بيئة العامل الذي يستقبل الطلب. تحقق من **testcodex → Settings → Variables and Secrets** الخاصة بوقت التشغيل، وليس Build variables. أضف القيمة كـ **Secret** باسم `FCM_SERVICE_ACCOUNT_JSON` ثم احفظ وانشر تغيير الأسرار. القيمة هي محتوى ملف حساب الخدمة الكامل، وليست `google-services.json`. بعد ذلك استخدم فحص Firebase دون إرسال في اللوحة.

`keep_vars: true` يحافظ على المتغيرات التي تُدار في لوحة Cloudflare عند نشر Wrangler. بدون هذا الخيار، قد تُحذف متغيرات النص العادي التي لا يذكرها ملف الإعداد. الخيار لا يعيد قيمًا مفقودة، ولا يحوّل النص العادي إلى Secret؛ ينبغي حفظ حساب الخدمة كسرّ. إذا أنشأت محاولة إعادة إرسال مسودة قبل هذا الخطأ، استخدم **إرسال الآن** لتلك المسودة بعد تصحيح الإعداد بدل إنشاء نسخة أخرى.


## لوحة الإدارة والمشتركون وأنواع الإشعارات — 0.1.8

واجهة الإدارة الجديدة تستخدم قائمة جانبية داكنة، أزرارًا ذهبية، بطاقات إحصائية، جدول حملات ورسومًا من البيانات الفعلية. تعمل بالعربية وتتكيف مع الهاتف. البحث يرشّح الحملات والمشتركين والأجهزة والأنواع. الرسم الأسبوعي يجمع قبول Firebase والنتائج الفاشلة/غير المعروفة حسب تاريخ إنشاء الحملة بتوقيت UTC؛ لا يمثل وصول الإشعار أو فتحه. توزيع الحالات يعتمد على أحدث 100 حملة، والبطاقات الإجمالية تشمل السجلات كلها. قنوات SMS والبريد وUSSD والموافقات غير مضافة.

ترحيل `0003_notification_types_subscribers.sql` يضيف المشتركين، الجمهور المحدد، أنواع الإشعارات ونسخة قالب العملية. يطبّقه أمر النشر المعتاد **`npm run db:remote && npm run deploy`** من مجلد **`cloudflare`**. لا يستبدل قاعدة البيانات ولا سجلات الحملات القديمة.

1. افتح **المشتركون** وأضف رقم المشترك في نظامك واسمه. الرقم فريد؛ إدخاله مجددًا يحدّث الاسم.
2. من **الأجهزة والربط** اختر المشترك لكل جهاز واحفظ الربط. يمكن للمشترك امتلاك عدة أجهزة.
3. في الحملة اختر **مشتركون محددون** ثم الأسماء. الاستهداف يجمع اختيار المشترك مع المنصة والشريحة؛ الأجهزة غير المرتبطة بهؤلاء المشتركين لا تستقبل الحملة. الجمهور الفارغ لا يتحول إلى جميع المستخدمين. إعادة الإرسال ونسخ الحملة يحتفظان باختيار المشتركين، وتستهدف النسخة الأجهزة النشطة المطابقة وقت إرسالها.
4. من **أنواع الإشعارات** أضف نوعًا بمفتاح ثابت، اسم، عنوان ونص؛ أو عدّل نوعًا وعطّله. يدعم القالب `{amount}` و`{operationId}` فقط. في Android 0.1.8 افتح **التجارب** لاختيار نوع مفعّل واختباره.

مسارات إدارة المشتركين وربطهم بالأجهزة وتعديل الأنواع تتطلب جلسة المدير وحماية الأصل. `GET /api/mobile/notification-types` يتطلب اعتماد الجهاز ويعيد الأنواع المفعّلة. مسار العمليات التجريبية يقبل `eventType`؛ الافتراضي `invoice_paid` لدعم الإصدارات القديمة. منع التكرار يتحقق من النوع والمبلغ معًا؛ تغييرهما لنفس `requestId` يرجع 409. تعطيل النوع يمنع عمليات جديدة، بينما العمليات الموجودة تحتفظ بنصها وحالتها دون إعادة إرسال تلقائية.

هذه الميزات لا تربط نظام المشتركين أو الفواتير الحقيقي تلقائيًا؛ هوية المشترك تُعيّن من اللوحة حاليًا، والعمليات أحداث اختبار فقط.


## التسجيل والدخول برقم الهاتف — 0.1.9

الترحيل `0004_mobile_accounts.sql` يضيف جدول `mobile_accounts` وربط جلسة الجهاز بالحساب، مع الحفاظ على الاشتراكات والسجلات السابقة. يُطبق بواسطة أمر النشر الحالي `npm run db:remote && npm run deploy` من `cloudflare`.

- `POST /api/mobile/register`: الاسم `name`، الهاتف الدولي `phone`، كلمة المرور `password`، رمز FCM `token` والمنصة `android`. ينشئ الحساب والمشترك معًا ويصدر اعتماد الجهاز. يحوّل `00` إلى `+` ويزيل المسافات والفواصل ويدعم أرقام الكتابة العربية.
- `POST /api/mobile/login`: الهاتف وكلمة المرور وبيانات الجهاز. يتحقق من كلمة مرور مشتقة بـPBKDF2 مع salt عشوائي؛ لا يخزن كلمة المرور كنص ولا يعيدها للعميل. يصدر جلسة 30 يومًا ويحدد مالك الجهاز من الحساب على الخادم.
- `GET /api/mobile/me`: معلومات حساب الجلسة الحالية فقط. بقية مسارات الأجهزة والتجارب تستخدم الاعتماد نفسه.
- `DELETE /api/mobile/device`: خروج الجهاز الحالي وإيقاف إشعاراته وإلغاء جلساته؛ لا يلغي الأجهزة الأخرى للحساب.

الحسابات الجديدة تظهر تلقائيًا ضمن **المشتركون** باسمها ورقم الهاتف مع شارة حساب التطبيق. في **الأجهزة والربط** يظهر الربط التلقائي ولا يمكن تغييره يدويًا لحساب آخر؛ يجب الخروج والدخول بالحساب الآخر من الجهاز. إعادة الدخول على الجهاز نفسه تدوّر جلسته؛ الانتقال لحساب آخر بعد الخروج يخصص معرّف جهاز جديدًا لمنع تسريب سجل عمليات المستخدم السابق. جلسات الحساب تتأكد من بقاء الجهاز نشطًا ومن تطابق مالكه. رمز الربط الإداري لا يحوّل جهاز حساب موجود إلى جلسة مجهولة.

التسجيل محدود إلى 5 محاولات في الساعة لكل IP، والدخول إلى 15 محاولة في 15 دقيقة لكل IP؛ يوجد أيضًا حد مستقل للهاتف. التسجيل المتزامن لنفس الرقم لا ينشئ حسابين ولا يسمح باستبدال كلمة مرور الحساب الفائز. رقم موجود في سجل المشتركين قبل التسجيل لا يمكن ادعاؤه بالتسجيل العام. لا يستخدم هذا التنفيذ Firebase Auth أو SMS؛ Firebase مستخدم لإشعارات FCM فقط. الأرقام غير موثقة، واستعادة كلمة المرور وتفعيل الحسابات المستوردة غير مضافة. الحماية على Workers Free تبقى خاضعة لحصة CPU وطلبات D1؛ اختبارات التطوير ليست اختبار حمل إنتاجي.
