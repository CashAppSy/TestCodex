# نشر لوحة نبض

هذا المسار يستخدم خادم Linux واحدًا مع Docker Compose: لوحة الإدارة، عامل الحملات المجدولة، وCaddy لشهادة HTTPS وتجديدها تلقائيًا. اللوحة والعامل يشتركان في قاعدة SQLite على volume دائم. لا تستخدم عدة خوادم أو نسخ web بهذا الإعداد؛ يتطلب التوسع تغيير قاعدة البيانات.

## المطلوب خارج المشروع

1. خادم VPS بنظام Ubuntu أو Debian، مع Docker وDocker Compose. يفضّل 2 CPU و4 GB RAM لبناء الصورة على الخادم، وقرص دائم 20 GB أو أكثر.
2. دومين أو نطاق فرعي مثل `notifications.your-domain.com`، مع سجل DNS من نوع A يشير إلى IP الخادم. أضف AAAA فقط إذا كان IPv6 مهيأ فعلًا. افتح منفذي 80 و443، ومنفذ SSH لإدارتك.
3. ملف حساب خدمة للمشروع `nabed-549b0` بصلاحية FCM، محفوظ على الخادم خارج مجلد المشروع. استبدل المفتاح الذي رُفع في المحادثة قبل النشر، وانقل البديل عبر قناة آمنة، دون إضافته إلى Git.

لا يحتاج تطبيق Android إلى مفتاح الخادم؛ يتصل بعنوان اللوحة ويحصل على رمز ربط من المدير. لا توجد استضافة أو دومين أُنشئت تلقائيًا بهذه الملفات.

## الإعداد الخاص قبل فتح الموقع

ضع المشروع على الخادم، وملف حساب الخدمة مثلًا في `/srv/nabdh-secrets/firebase-admin.json` بصلاحيات قراءة مقيدة. من جذر المشروع:

```sh
cp deploy/.env.example deploy/.env
chmod 600 deploy/.env
```

حرّر `deploy/.env`: اكتب الدومين والبريد ومسار الملف، وأنشئ قيمة عشوائية لـ`CMS_DEVICE_API_KEY` بطول 32 حرفًا على الأقل باستخدام مدير أسرار أو أداة توليد محلية. لا تنسخ القيمة إلى التطبيق أو المحادثة.

```sh
docker compose -f deploy/compose.yaml --env-file deploy/.env config --quiet
docker compose -f deploy/compose.yaml --env-file deploy/.env up -d --build web
```

اللوحة الآن تستمع على loopback الخادم فقط، وCaddy والعامل لم يبدآ. من حاسوبك أنشئ نفق SSH:

```sh
ssh -L 3000:127.0.0.1:3000 USER@SERVER_IP
```

افتح عنوان loopback المحلي على منفذ 3000 ومسار `/setup` وأنشئ حساب المدير بكلمة مرور قوية. تحقق أن الحساب أُنشئ وأن `/setup` لم يعد يسمح بإنشاء مدير جديد. إعداد cookies الآمنة مخصص لـHTTPS؛ إذا لم يستمر تسجيل الدخول عبر النفق، سجّل الدخول لاحقًا عبر الدومين. **أنشئ المدير قبل تشغيل الخدمات العامة** حتى لا يتمكن زائر من أخذ حساب المدير الأول.

## تشغيل HTTPS والحملات

بعد إنشاء المدير وضبط DNS، نفّذ على الخادم:

```sh
docker compose -f deploy/compose.yaml --env-file deploy/.env --profile public up -d
docker compose -f deploy/compose.yaml --env-file deploy/.env ps
```

سيصدر Caddy شهادة HTTPS للدومين؛ افتح `https://YOUR_DOMAIN/login` وسجّل الدخول. تحقق من شاشة إعدادات الإشعارات. العامل يعالج الحملات المقصودة المجدولة كل 30 ثانية. ظهور الموقع أو قبول FCM لطلب لا يثبت وصول الإشعار إلى الهاتف.

على Android، أدخل عنوان HTTPS، ثم رمز الربط من صفحة **الأجهزة والجمهور**. اختبر حملة موجهة إلى منصة Android وشريحة `test` بعد ظهور جهازك. يلزم APK حقيقي؛ معاينة المتصفح لا تستقبل FCM.

## البيانات والتحديث

البيانات في volume `cms_data`، وشهادات HTTPS في volumes الخاصة بـCaddy. لا تستخدم `docker compose down -v` لأنه يحذف هذه البيانات. خذ نسخة احتياطية خارج الخادم قبل التحديث؛ لإجراء نسخة ملفات SQLite بسيطة أوقف web والعامل أولًا وانسخ مجلد البيانات كاملًا، ثم أعد تشغيلهما. اختبر استعادة النسخة، ولا تعتمد على حجم الملف وحده.

للتحديث، حدّث ملفات المشروع ثم أعد البناء والتشغيل بالأوامر نفسها. احتفظ بـ`deploy/.env` وملف حساب الخدمة وvolumes. هذا النشر لم يُنفّذ على استضافة عامة؛ تحتاج توفير الخادم والدومين أولًا.
