# Cash Mobile · تطبيق Android لاختبار الإشعارات

تطبيق React Native / Expo مهيأ لاستقبال **FCM Tokens الحقيقية** من نفس مشروع Firebase المستخدم في لوحة Cash Mobile. يعرض صندوقًا محليًا للإشعارات، تفاصيل الرسالة، وفتح رابط `nabdh://campaign/<id>`. لا يحتوي مفتاح حساب الخدمة أو مفتاح API الخاص باللوحة.

النسخة `0.1.6` تستخدم ملف PNG الأصلي المرفق من المستخدم دون إعادة رسمه أو تغيير بكسلاته. ملف `assets/cash-mobile.png` شفاف بالفعل، بما فيه الفراغات داخل المحفظة والأوراق. أيقونة التطبيق على Android 8 وما بعده تستخدم موردًا تكيفيًا بخلفية `@android:color/transparent` ولوغو أصلي في طبقة المقدمة، مع هامش لحمايته من القص. هذا يتجنب تحويل أيقونة PNG القديمة إلى أيقونة تكيفية بلوحة خلفية تلقائية. على الإصدارات الأقدم تُستخدم صورة PNG الأصلية الشفافة. المظهر النهائي يحتاج التحقق على الهاتف؛ قد تطبق بعض المشغلات تنسيقها الخاص. أيقونة الإشعار الصغيرة تُشتق الآن من اللوغو الأصلي نفسه، دون الرسم البديل السابق، ويستخدم التطبيق والخادم لون تمييز رماديًا بدل الأصفر. Android يعرض الأيقونة الصغيرة بلون واحد وقد تضيف واجهة الهاتف شارة حولها. الصورة الملونة الكبيرة للإشعار في المقدمة تُقرأ محليًا من مورد اللوغو، وفي الخلفية يرسل Cloudflare رابط الصورة العام في FCM. تحميل الصورة في الخلفية يتطلب وصول الهاتف إلى الرابط. احتُفظ بالحزمة `com.nabdh.testapp` ومشروع Firebase ومسارات الربط؛ يمكن تثبيتها كتحديث للنسخة السابقة عند تطابق التوقيع.

## ما الذي نحتاجه من Firebase؟

1. **Project ID** من Firebase → Project settings → General. يجب أن يكون نفس المشروع المستخدم لإرسال الحملات من الخادم.
2. **اسم حزمة Android**. الافتراضي في المشروع `com.nabdh.testapp`. يمكن تسجيل تطبيق اختبار جديد بهذا الاسم داخل مشروع Firebase الحالي، أو ضبط `ANDROID_PACKAGE` باسم تختاره قبل البناء.
3. **ملف `google-services.json` الخاص بتطبيق Android**: Firebase → Project settings → Your apps → Android → Download google-services.json. ضعه في `mobile/google-services.json`، أو اضبط `GOOGLE_SERVICES_FILE` لمسار الملف. يجب أن يتطابق اسم الحزمة في الملف مع إعداد التطبيق. هذا ملف إعداد العميل وليس ملف حساب الخدمة؛ يحتوي معرفات ومفتاح API للعميل، ولا يمنح صلاحية إرسال FCM الإدارية بمفرده.
4. **حساب الخدمة للخادم**: من إعدادات المشروع → Service accounts، جهّز حسابًا بصلاحية إرسال FCM HTTP v1. أدخل ملفه/قيمته **كسرّ على خادم اللوحة** في `FCM_SERVICE_ACCOUNT_JSON`، أو مسار آمن لملفه. لا تضع `private_key` في الموبايل، المستودع، أو المحادثة. Project ID وملف العميل وحدهما لا يسمحان للخادم بإرسال الحملات.
5. **عنوان HTTPS للوحة يمكن لهاتفك الوصول إليه**. الربط المباشر بعنوان loopback داخل cloud لا يصل من هاتفك؛ تحتاج نشر اللوحة أو شبكة محلية يمكنك الوصول إليها.

لا نحتاج كلمة مرور Google أو حسابك الشخصي. لا تحتاج بصمات SHA-1/SHA-256 لتجربة FCM الأساسية، لكنها قد تلزم إذا أضفت Google Sign-In أو App Check أو ميزات أخرى لاحقًا.

## معاينة الواجهة الآن، دون Firebase

من مجلد `mobile`:

```sh
npm ci
npm run web
```

المعاينة تعمل في المتصفح، وتوفر زر «تجربة إشعار محلي» وصندوقًا محفوظًا في المتصفح وفتح صفحة حملة تجريبية. **المحاكاة تضاف داخل واجهة التطبيق فقط؛ لا ترسل إشعار نظام ولا تختبر Firebase**. زر الربط معطل في الويب عمدًا. هذه ليست نسخة Web Push.

```sh
npm test
npm run typecheck
EXPO_OFFLINE=1 CI=1 npm run export:web
```

التطبيق يستخدم Expo SDK 57 وReact Native 0.86.3 والإصدارات المتوافقة في lockfile. استخدم `npm ci` بدل تحديث عشوائي للحزم.

## نسخة Android حقيقية

يتطلب البناء بيئة Android Studio/SDK وجافا بالإصدار الذي يدعمه قالب Gradle الحالي، وجهاز Android فعلي أو محاكي به Google Play Services. لا تعمل هذه الوحدات في **Expo Go**؛ تحتاج development build أو APK أصلي.

بعد إضافة ملف Firebase المطابق:

```sh
cd mobile
npm ci
npm run check:firebase
npm run android
```

`npm run android` يفحص الملف ثم ينشئ مشروع Android ويُثبت نسخة تطوير على الجهاز المتصل. شغّل `npm start` لMetro إذا لم يكن يعمل. هذه نسخة تطوير تحتاج Metro، وليست APK مستقلًا لتوزيعه على مستخدمين.

لبناء APK debug على جهاز مجهز بـ Android SDK:

```sh
npm run build:apk
```

ستجده عادةً في `android/app/build/outputs/apk/debug/app-debug.apk`. هذا APK تطوير يحتاج Metro أيضًا. عند تشغيل Metro من حاسوب متصل عبر USB، استخدم `adb reverse tcp:8081 tcp:8081` إذا لزم.

لبناء APK اختبار مستقل دون Metro لأجهزة ARM64:

```sh
EXPO_NO_TELEMETRY=1 NODE_ENV=production npm run build:apk:standalone
```

الملف الناتج `android/app/build/outputs/apk/release/app-release.apk` يتضمن حزمة الواجهة ويعمل على Android 7.0 أو أحدث. يحتاج Google Play Services لاستقبال FCM. يستخدم قالب Expo الحالي مفتاح توقيع التطوير حتى في هذا البناء؛ يصلح للاختبار المباشر، ويتطلب توزيع الإنتاج إعداد مفتاح توقيع خاص. لا تحتاج EAS أو خدمة بناء مدفوعة. إضافة `plugins/with-notification-color.cjs` تعالج تعارض لون الإشعار بين Expo وFirebase عند توليد Android؛ احتفظ بها في بداية قائمة plugins لأن تعديلات manifest تنفذ بترتيب عكسي.

تم التحقق من ملف Android للمشروع `nabed-549b0` والحزمة `com.nabdh.testapp`، وتوليد مشروع Android بنجاح. نجحت مصادقة حساب الخدمة وفحص FCM HTTP v1 باستخدام `validate_only`، دون إرسال إشعار. هذه الفحوص لا تثبت وصول إشعارات إلى هاتف؛ يلزم بناء التطبيق، وربطه بلوحة متاحة للهاتف، ثم اختبار جهاز حقيقي.

في بيئة cloud الحالية ثُبّت Android SDK وJava 17، وأصبح تنزيل React Native من `repo.reactnative.dev` متاحًا. نجح بناء APK مستقل لمعمارية `arm64-v8a`، وفحص توقيعه ووجود حزمة الواجهة داخله وفحص خلوه من مفتاح حساب خدمة Firebase. حجمه نحو 28 ميغابايت. أداة البناء المحلية تضبط SDK وJava والشهادات المعتمدة والـproxy وتعطل Expo telemetry لتجنب الكتابة في home غير القابل للكتابة:

```sh
NODE_ENV=production python3 /workspace/.nabdh-tools/build-android.py assembleRelease -PreactNativeArchitectures=arm64-v8a
```

هذه الأداة والـSDK إعدادات محلية للبيئة خارج المستودع. لم يُختبر الاستقبال على هاتف فعلي بعد. عنوان اللوحة المنشورة للربط: `https://testcodex.eng-ali-m-ibrahim.workers.dev`.

`ANDROID_PACKAGE` يغير الاسم قبل prebuild. `GOOGLE_SERVICES_FILE` يغير موقع ملف العميل. لا تستخدم ملف حساب الخدمة بدلًا من `google-services.json`. عند تغيير مشروع Firebase/اسم الحزمة بعد توليد مشروع Android، أعد توليد المشروع الأصلي بعد حفظ أي تغييرات يدوية؛ لا يعتمد التطبيق على ملفات Android مولدة محفوظة في Git.

## ربط آمن دون مفتاح الخادم داخل التطبيق

1. في لوحة نبض، سجّل دخول المدير ثم افتح **الأجهزة والجمهور**.
2. اضغط **إنشاء رمز ربط**. الرمز صالح 10 دقائق ولمرة واحدة، وإصدار رمز جديد يلغي السابق.
3. في نسخة Android، افتح **ربط اللوحة**. أدخل عنوان اللوحة والرمز، ثم امنح إذن الإشعارات.
4. يحصل التطبيق على FCM token ويرسل الرمز مع token إلى `POST /api/mobile/pair`. يُسجّل الجهاز ضمن شريحة `test`.
5. الخادم يعيد جلسة عشوائية خاصة بهذا الجهاز، مخزنة في Android SecureStore. الخادم يخزن hash لها فقط. الجلسة صالحة 30 يومًا؛ استخدم «إعادة الربط برمز جديد» عند انتهائها. هذا يمسح جلسة الربط المحلية فقط، ولا يدّعي إلغاء اشتراك الجهاز على الخادم.
6. عند تجديد FCM token، يحدث التسجيل عبر `PUT /api/mobile/device` باستخدام جلسة الجهاز. زر **تحديث تسجيل الجهاز** يفعل ذلك يدويًا إذا حدث التجديد أثناء إغلاق التطبيق.
7. **إلغاء الاشتراك وفصل الجهاز** يرسل `DELETE /api/mobile/device`، يعطل الجهاز، ويلغي جلساته. إذا تعذر الوصول للخادم، لا يمسح التطبيق الجلسة حتى تنجح العملية أو تطلب إلغاء التسجيل يدويًا.

رمز الربط يمنح تسجيل جهاز اختبار واحد، لذلك شاركه فقط مع جهازك. واجهة الربط العامة محدودة بـ120 محاولة في الدقيقة لكل عملية خادم. هذه حماية أولية؛ عند النشر الواسع أضف حدودًا على بوابة الدخول. الربط منفصل عن API الخادم `CMS_DEVICE_API_KEY`؛ لا تضع هذا المفتاح العام في التطبيق.

## أول إشعار حقيقي

1. تأكد من إعداد حساب الخدمة على اللوحة وتشغيل FCM API HTTP v1، وأن الجهاز يظهر في شريحة `test`.
2. أنشئ حملة في اللوحة، اختر **Android** وشريحة **test** تحديدًا.
3. أدخل عنوانًا ونصًا، ورابطًا اختياريًا مثل `nabdh://campaign/hello`.
4. احفظ الحملة ثم اضغط إرسال الآن وأكد الإرسال.
5. جرّب التطبيق مفتوحًا: تحفظ الرسالة في الصندوق ويظهر إشعار نظام محلي باستخدام محتوى FCM.
6. جرّب التطبيق في الخلفية: يعرض Android إشعار FCM. اضغطه لفتح التطبيق، ويُفتح مسار الحملة إذا كان رابط `nabdh` صالحًا.
7. جرّب فتح التطبيق من إشعار بعد إغلاقه العادي. **Force stop** من إعدادات Android قد يمنع الرسائل حتى تشغيل التطبيق مجددًا. الأجهزة بدون Google Play Services لا تستقبل FCM بهذا التنفيذ.

تستعمل نسخة التطبيق قناة `nabdh`. يعالج Firebase عرض الإشعارات في الخلفية؛ لا ينشئ handler الخلفية إشعارًا محليًا ثانيًا. المعالج المحلي ينشئ إشعار النظام في المقدمة فقط. Expo notification service منخفضة الأولوية عن خدمة RNFirebase في manifest.

## ما الذي تثبته النتائج؟

الواجهة تعرض الفرق بين **إشعار FCM** و**محاكاة محلية**. سجل الجهاز يحفظ آخر 100 رسالة ويمنع تكرار message ID عند الاستلام والفتح. يُعاد تحميله عند العودة للتطبيق. إذا منع النظام معالج الخلفية، قد لا تظهر الرسالة في السجل حتى فتحها؛ لا يدّعي السجل أنه إحصاء شامل لكل رسائل Android.

توقيت الجهاز محلي. روابط التطبيق المدعومة `nabdh://campaign/<id>` وروابط HTTPS الخارجية التي يفتحها المستخدم صراحةً. لا تُنفذ `javascript:` أو روابط ملفات أو HTTP من رسائل الإشعارات. فتح الحملة التجريبية لا يحمّل بيانات حملات إدارية؛ إنه مسار لإظهار تجربة الفتح.

لا تُرسل هذه النسخة وصولًا/فتحًا إلى لوحة CMS، ولا تفحص receipt خاصًا بـExpo. قبول الطلب لدى FCM في اللوحة يظل منفصلًا عن استلام الجهاز. إعداد Firebase متوفر، لكن الاستقبال على Android لم يُختبر بعد لعدم توفر هاتف متصل أو محاكي جاهز.

أثناء التطوير المحلي فقط، يسمح التطبيق بعنوان HTTP لشبكة محلية عندما تكون `__DEV__=true`. قد تحتاج `ALLOW_INSECURE_DEV_HTTP=true` **وقت prebuild** في نسخة debug. المحاكي يستخدم `10.0.2.2` للوصول لحاسوبك، وليس `localhost`. لا تفعّل هذا الإعداد في release؛ استخدم HTTPS في النشر.

ملفات `google-services.json` وملفات البيئة وAndroid المولد وملفات التوقيع مستثناة من Git. لا تضع مفاتيح حساب الخدمة في أي ملف داخل تطبيق الموبايل.
